## 28번 선택 영역 보정·원본 픽셀 적용

23개 보정/필터의 범위 밖 원본 불변, 반전·타원·분수 알파/페더, HDR·음수 RGB·투명도, 선택 영역 자동 레벨과 부분 합성 일치를 검사했다. 범위는 편집 시작 시 고정해 이후 선택 해제와 구분하며 이동/반복 변형/취소·자르기·뒤집기·크기 변경·래스터화·원본 영역 확장에 따라간다. 범위만 있는 기본 보정이 통과 그룹을 격리하거나 외관을 바꾸지 않는 것도 검사했다.

실제 egui 입력으로 범위 켜기/끄기·취소/설정 적용/재편집·선택 해제 후 범위 복원·그룹 원본 픽셀 적용·잠금 보호와 한 번 실행 취소/재실행을 확인했다. `.rphoto` v7에서 추가한 별도 범위(현재 v8)의 PNG/메타데이터·HDR 원본 왕복, 자산 누락/크기 불일치/잘못된 이전 버전 범위 거부와 실패 시 기존 파일 보존을 검사했다. 현재 버전 1–7 읽기를 유지한다.

배경 의존 통과 그룹은 선택 밖의 기존 합성을 유지하고 페더/그룹 불투명도/마스크를 한 번 반영한다. 해당 그룹의 원본 적용은 거부하고 이유를 표시한다. PSD/PSB는 이 경우 외관을 유지한 전체 합성 한 레이어로 변환하며 저장 화면에서 안내한다. 그 밖의 선택 보정은 기존 픽셀 변환 경로의 32비트/HDR 외관 왕복을 확인했다. 이 검사를 네이티브 조정 구조 보존 완료로 표시하지 않는다.

예제: `qa-output/adjustment-scope/selected-hdr.rphoto/.psd/.psb`, `pass-through.rphoto/.psd/.psb`. `bad-*`는 손상 거부 검사용 프로젝트다. 별도 조정 레이어는 29번에서 구현했다. 배경 의존 그룹의 모든 파괴 편집 경로는 미완료 목표로 유지한다.

## 29번 별도 조정 레이어·마스크·편집 구조 저장

현재 레이어 위 또는 그룹 안에 원본을 중복하지 않는 별도 조정 레이어를 생성한다. 같은 부모의 아래 합성에 적용하고 통과/격리 그룹·클리핑 기준의 입력을 구분한다. 원본·HDR·음수 RGB와 아래 합성의 알파를 유지하며 표시·불투명도·블렌드·선택 범위·분수 마스크·복제·재편집을 연결했다. 마스크의 그리기·독립 변형/취소·그룹 반복 변형·자르기·뒤집기·리사이즈와 원본 공유도 검사했다.

자동 레벨은 조정에 들어오는 아래 합성을 사용하며 위 레이어와 조정 자신의 보정은 제외한다. 위치에 의존하는 노이즈/비네트/선택 범위의 부분 합성은 전체와 일치하며 공간 필터는 기존 전체 작업 경로를 사용한다. 실제 egui 입력은 생성/취소·생성/적용 한 번 실행 취소·재편집/취소·자동 레벨·픽셀 원본 보호를 검사했다.

`.rphoto` v8에 조정 유형·설정·범위·분수 마스크·원본을 보존하고 v1–7 읽기를 유지한다. 잘못된 유형/그룹/요소 조합과 이전 버전의 조정 레이어를 거부하며 실패 시 기존 파일을 유지한다. 병합은 기존 외관과 후보 결과를 비교해 배경 의존으로 달라지는 경우 원본과 이력을 유지하고 대상 추가를 안내한다. 직접 픽셀 적용/복사/래스터화는 조정의 대상에 맞는 대안을 표시한다.

PSD/PSB는 별도 조정 레이어가 있으면 현재 전체 합성 한 레이어로 변환하며 저장 전에 안내한다. 32비트 왕복 외에 `verify_adjustment_outputs.py`가 Rust 렌더러/로더를 사용하지 않고 노출·선택/페더·마스크·불투명도의 수식으로 파일 합성을 확인했다. Photoshop 네이티브 조정 유형/설정/마스크 구조 보존은 미완료 목표다. 예제: `qa-output/adjustment-layer/selected-hdr.rphoto/.psd/.psb`, `bad-*`는 손상 거부용이다.

## 실제 검증과 남은 범위

포인터·키 검사는 egui 입력을 자동으로 구동한 검사다. 최신 기능의 실제 Windows 창 조작은 수행하지 못했다. 화면 연결이 `windows sandbox failed: helper_unknown_error: setup refresh had errors` 및 `trusted Node process exited unexpectedly`로 초기화에 실패한 이력이 있으며 반복 재시도하지 않았다. Photoshop/Compositor에서 직접 양방향으로 다시 여는 검사도 수행하지 않았다.

화면 축소 필터, RAW, 전체 ICC/광색역/CMYK/Lab/HDR 표시, 네이티브 PSD 텍스트/벡터/효과/스마트 오브젝트/고정밀 마스크, 애니메이션/페이지, 추가 코덱 변형/출력, `.comp`, 필압/객체 선택/확장 리터칭, GPU/타일/메모리 예산/대형 문서 성능 및 Windows 환경/서명/업데이트 검증은 남아 있다. 렌즈 프로파일 자동 보정, 외부 파일의 수정 시각/크기를 유지하는 변경과 다른 앱 동시 저장 잠금도 별도 목표다. 구체적인 상태는 체크리스트 표를 기준으로 한다.

사용자의 요청으로 30분 간격 heartbeat 자동 진행을 껐다(automationId: `automation`, PAUSED). 앞으로는 사용자가 작업을 명령할 때만 구현을 진행하고 자동화를 임의로 다시 켜지 않는다. 기능 하나씩 구현·검증·기록한 후 다음 기능을 진행하는 순서는 유지한다. 사용자가 게임 중이므로 별도 해제 전까지 computer use·화면 캡처·키보드/마우스 자동화·네이티브 앱 실행·창 포커스 변경은 금지한다. 화면을 조작하지 않는 검사만 수행한다.

## 30번 레이어 경계 밖 필터 확산

가우시안·모션 블러·블룸의 합성 버퍼와 위치를 확장하며 기본/이전 설정은 기존 경계를 유지한다. 점 보정은 원래 좌표에서 처리하고 렌즈 중심도 원본 기준으로 유지한다. 블룸은 하이라이트의 선곱 광량과 분수 알파를 확산해 투명 영역에 빛을 만들며 숨은 RGB는 섞지 않는다. 선택 범위와 마스크는 확장 좌표를 원본으로 환산한다. 원본 적용은 마스크 문서 좌표와 회전/배율/원근·효과를 유지하고 한 번 실행 취소한다. 파일/변형/UI 적용에서 외곽 크기·투영을 검증한다.

신규 자동 검사 7개: 1픽셀 모션의 독립 기대값·가우시안 알파 총량/HDR/음수 RGB·블룸 외곽/숨은 RGB, 선택 밖 원본·노이즈/비네트 좌표, 연결/독립 마스크와 변형/효과/원본 적용/이력, 렌즈 중심 독립 줌 수식, 8/16/32비트 프로젝트와 PSD/PSB, 크기·외곽 지평선 거부/기존 파일 보존, 화면 조작 없는 UI 옵션·적용/취소·한 번 실행 취소. 양자화 출력은 알파와 선곱 RGB 오차로 비교한다. 전체 검사는 208개 통과·실패 0(수동 진단 1개 제외).

예제: `qa-output/filter-bounds/expanded8/16/32.rphoto/.psd/.psb`. `.rphoto` v8의 추가 기본값 필드로 저장하며 v1–7 읽기를 유지한다. 실제 Windows 창·Compositor 외관 비교는 수행하지 않았다.

JxlDecoder의 정수/회색조 경로가 범위 밖 RGB와 float 회색조를 자르던 부분을 JxlImage의 행 단위 float 스트림으로 대체했다. 색과 알파 각각의 비트 깊이·float 여부를 고려하고 범위 밖 값은32비트로 유지한다. 미리 곱한 α는 독립 편집 RGB로 나누고 α0의 숨은 값은 유지한다. JPEG XL의 자체 방향이 적용된 스트림을 받아 EXIF 방향을 중복 적용하지 않는다. 머리글부터 할당 추적을 설정하고 입력 크기/치수와 불완전 첫 프레임을 검사한다. 추적되지 않는 모든 할당의 엄격한 총예산/전체 ICC/CMYK 채널/메타데이터·여러 프레임·추가 채널 편집/인코더는 남음.

[libjxl/conformance](https://github.com/libjxl/conformance) 커밋 b1d0f990b03e57bf6d137c365cd5dc8b470b9191의6종을 내려받고 공식 SHA-256과 기준 float/ICC를 유지했다. `alpha_triangles`, `alpha_nonpremultiplied`, `alpha_premultiplied`, `sunset_logo`, `lossless_pfm`, `grayscale_jpeg`는 모두 범위 밖 값이 있어32비트로 유지한다. 공식 NPY는 압축만 적용했으며 해제한 원본 해시도 확인한다. 일반 α·방향/회색조·HDR 최대 픽셀 오차는 0~1.85e-6이고32비트 lossless_pfm은 float 값이 정확히 일치한다. associated α는 원래 premultiplied 값으로 되돌려 기준과 비교한다.

VarDCT `alpha_premultiplied` RGB 최대 오차는 약0.000166이다. 코퍼스 JSON의 공통3.815e-6은 α에 맞춰져 있으며 RGB는 그보다 오차가 크다. [jxl-oxide 자체 검사](https://github.com/tirr-c/jxl-oxide/blob/f4dce3f/crates/jxl-oxide-tests/tests/conformance/mod.rs)와 같은 RGB peak0.004/RMS0.0001, α peak/RMS3.815e-6 기준으로 확인했다. 독립 결과에 코퍼스 공통 기준 통과 여부를 따로 기록하며 이 RGB의 엄격한 공통 기준/전체 ISO 적합성 통과는 주장하지 않는다. 전체 색 관리와 디코더 정확도 확대는 계속 남음.

신규2개 검사:6종 전체 기준 float/α/방향·파일 열기의 작업 버퍼·원본 불변/.rphoto 복원, EXIF8 컨테이너(기존 경로가 방향8을 읽음 확인)에도 JPEG XL 픽셀 방향 유지·잘린/잘못된5종 입력의 오류와 파일 보존. 별도 `verify_jxl_inputs.py`가 원본/압축/입력/ICC 해시·전체 float 픽셀/치수·오차와 α를 독립 비교한다. 예제 `tests/fixtures/jxl`, 출력/측정 `qa-output/jxl`. 전체267개 통과·실패0·진단1 제외, 서식/경고와 두 빌드 성공. 다음은 TIFF32비트 부동소수점 예측 압축이며 자동화 중지와 화면 조작 금지를 유지한다.

## 46번 TIFF 부동소수점 예측과 압축 호환성

32비트 TIFF/BigTIFF에 부동소수점 예측(Predictor 3)을 연결했다. LZW·Deflate 3수준에서 사용하며, 무압축/PackBits는 예측 없이 6개 압축 선택을 모두 유지한다. 정수 수평 예측도 LZW·Deflate에만 적용한다. 무압축/PackBits의 예측을 무시하는 독립 리더에서 잘못 표시되던 기존 조합을 옵션 화면과 저장 검증에서 막았다. 다중 페이지/ICC·메타데이터와 외부 Photoshop 검증은 남는다.

로컬 tiff 0.11.3 패치는 행별 MSB 바이트 평면 재배열과 채널 간격 차분을 수행한다. 원본 전체를 복사하지 않고 스트립 단위로 압축한다. [Adobe TIFF 저장 설명](https://helpx.adobe.com/photoshop/desktop/save-and-export/save-files/save-in-tiff-format.html), [libtiff 예측 구현](https://gitlab.com/libtiff/libtiff/-/blob/5e18004500cda10d9074bdb6166b054e95b659ed/libtiff/tif_predict.c)을 대조했다. 라이선스와 [변경 안내](../../vendor/tiff/LOCAL_CHANGES.md)를 보존했다.

1/16/317px 폭과 여러 스트립, 4개 압축×classic/BigTIFF의 24개 파일에서 HDR·음수·signed zero·알파의 float 비트가 일치했다. Python tifffile/별도 LZW·zlib·NumPy 역변환으로도 전체 픽셀 비트가 일치했다. 큰 완만한 기준 이미지의 합계 파일 크기는 일반 압축 1,863,628바이트에서 예측 400,650바이트로 줄었다. 일반 TIFF의 호환 조합 52개도 독립 복원했다(이전 37번의 60개 중 무압축/PackBits+수평 예측 8개는 호환성 오류로 제외하고 저장 시 거부). 라이브러리 내부 16비트 half·64비트 double 회색조의 IEEE 비트/여러 스트립도 검사했으며 앱의 해당 출력 지원을 뜻하지 않는다. 옵션 포인터 전환·압축 변경 시 예측 해제·기존 파일/원본 보존을 검사했다.

전체 269개 통과·실패 0개·수동 진단 1개 제외. 서식/경고 검사와 두 빌드가 통과했다. `verify_tiff_outputs.py`, `verify_tiff_predictor.py` 결과와 예제는 `qa-output/tiff-output`, `qa-output/tiff-predictor`에 있다. 실제 Windows 창/Photoshop은 실행하지 않았다.

## 47번 회색조 PSD/PSB 읽기·정밀도·프로젝트 보존

회색조 8/16/32비트·한 색 채널/투명도·네 가지 압축과 그룹/클리핑/픽셀 마스크를 읽는다. 외부의 아래→위 레코드 순서를 사용하며 원래 값을 같은 정밀도의 중성 RGB 작업 버퍼에 유지한다. 파일 열기에서 현재 RGB 작업/출력 변환을 안내하고 회색조 ICC를 프로젝트에 보존한다. RGB 출력에는 색 공간이 다른 ICC를 붙이지 않으며 저장 화면에도 안내한다. 고비트 입력의 그룹 표시용 자산을 잘못된 정밀도로 저장해 프로젝트 복원이 실패하던 문제도 수정했다.

[Adobe 파일 규격](https://www.adobe.com/devnet-apps/photoshop/fileformatashtml/)을 대조한 별도 Python struct/zlib 인코더의 합성 입력72종을 psd-tools1.10.9로 복원했다. Rust 입력 배열96개는 독립 검사에서 전체 float 비트가 일치했다. 정수 끝점/한 단계 차이·float 음수/HDR/signed zero·투명도/그룹 순서/마스크/클리핑·가이드·.rphoto 원본 비트/리소스 복원과 잘린 파일/NaN/잘못된 채널/지원하지 않는 모드 거부를 검사했다. 중성 RGB 출력3종을 psd-tools로 다시 읽어 채널 값과 부적합 ICC 제외도 확인했다. 합성 ICC 헤더는 색 공간 검사 전용이며 실제 색 변환 기준 파일이 아니다. 입력 원본을 변경하지 않았다.

전체271개·기존 PSD/PSB 압축24종 독립 검사·서식/경고 검사·두 빌드 통과. 예제 `tests/fixtures/gray-psd`, 결과 `qa-output/gray-psd`, 독립 검사 `verify_gray_psd_inputs.py`를 보존했다. 회색조 네이티브 출력/ICC·추가 알파/별색/CMYK/Lab·고정밀 마스크·Photoshop 왕복은 미완료다. 기존 RGB 레코드 순서의 외부 호환성 문제는 다음48번으로 분리했다. 실제 창/외부 앱은 실행하지 않았다.

## 48번 RGB PSD/PSB 외부 레이어·그룹 순서와 블렌드 레코드

RGB 읽기/쓰기를 외부의 아래→위 레코드 순서에 맞췄다. 채널 스트림을 각 레코드와 먼저 연결한 뒤 부모를 구성해 순서를 바꿔도 값/마스크가 다른 레이어에 붙지 않는다. 이전 개발 파일의 그룹 순서는 첫 구분자로 감지하며, 그룹 없는 이전 파일은 파일 메뉴/명령 검색의 ‘이전 개발 PSD/PSB 열기…’로 위→아래 순서를 지정한다. 이 경로는 원본 저장 위치 없는 문서로 열어 원본 파일을 보관한다. 새 출력은 외부 순서를 사용한다. 명령104개·도구19개·사용자 키38개다.

폴더 lsct/8BIM의 별도 블렌드 값을 읽기/쓰기에 반영했다. 일반 레코드 norm보다 폴더 pass/mul 설정을 반영하고 잘못된 서명/미지원 블렌드를 거부한다. [Adobe lsct 규격](https://www.adobe.com/devnet-apps/photoshop/fileformatashtml/), [psd-tools 그룹 구성](https://github.com/psd-tools/psd-tools/blob/main/src/psd_tools/api/psd_image.py)을 대조했다.

psd-tools1.10.9가 쓴 외부48종/이전순서48종의8/16/32비트·PSD/PSB·4압축·그룹/독립 레이어에서 순서·ID·부모/클리핑·RGB/α/마스크·프로젝트·원본 보존을 검사했다. 신규48개 출력의 구조/픽셀과 저장된 합성 평면·중첩 그룹2종·기존 압축 그룹24종도 psd-tools로 독립 확인했다. 실제 백그라운드 이전 파일 열기·새 탭/저장 위치/이력·문서 없음/작업/모달/변형 보호를 창 없이 검사했다.

전체274개·서식/경고 검사·두 빌드 통과. 예제 `tests/fixtures/rgb-psd-order`, 출력 `qa-output/psd-order`, 검사 `verify_psd_order_outputs.py`를 보존했다. 독립 리더의 RGB white matte 제거에서 합성 표시 오류를 추가로 발견했으며 이48번 검사는 저장 평면까지 확인한다. 합성 미리보기의 외부 표시/읽기 표현 수정은 바로 다음49번이다. 이 단계의 성공을 전체 PSD/Photoshop 외관 호환으로 표시하지 않는다. 실제 창/Photoshop은 실행하지 않았다.

## 49번 RGB PSD/PSB 투명 합성 미리보기의 흰 배경 표현

RGB 합성 평면을 색×알파+(1−알파)로 쓰고, 평면 외부 입력은 알파를 복원한다. RGB 원본 레이어는 비연관 채널의 원래 비트를 유지한다. [psd-tools NumPy 구현](https://github.com/psd-tools/psd-tools/blob/main/src/psd_tools/api/numpy_io.py)의 흰 배경 제거와 설치된1.10.9의 독립 표시 값을 대조했다. 기존 straight 합성 파일은 ‘이전 개발 PSD/PSB 열기…’ 경로에서 유지한다. 불투명 입력/회색조에는 RGB 합성 복원을 중복 적용하지 않는다. 비정상 알파/비유한 값/표현 불가능한 복원 색을 거부한다.

별도 Python 인코더의 평면48종(8/16/32비트·PSD/PSB·4압축·알파/불투명)과 이전 표현24종을 검사했다. 알파0/1·한 정수 단계/1/65535·HDR/음수/signed zero·불투명 값을 포함한다. 새48종 출력의 원본 레이어 비트, 저장된 흰 배경 평면과 표시 RGB×알파를 psd-tools로 독립 확인했다. 기존 순서48종도 독립 표시 검사로 확대하고 고정밀4종·압축24종·보정/톤 대비의 독립 합성 수식을 흰 배경 표현으로 검증했다. 전체276개·서식/경고 검사·두 빌드 통과.

낮은 알파에서는 합성 평면의 양자화가 나눗셈 뒤 확대되므로 정확한 레이어 비트와 알파를 곱한 표시 오차를 구분한다. 외부 합성만 있는 알파0 픽셀의 숨은 색은 복구할 수 없어 검정으로 정규화한다. 원래 레이어의 숨은 색은 유지된다. 해당 psd-tools 버전의 float 읽기 전용 보기 오류는 독립 복원한 같은 바이트를 writable buffer로 전달하는 검사 어댑터로 피했다. 설치 라이브러리를 수정하지 않았다. 실제 Photoshop/Windows 창은 실행하지 않았으며 전체 색 관리/다른 색 모드/추가 채널·고급 구조/고정밀 마스크와 Photoshop 왕복은 남는다. 예제 `tests/fixtures/psd-matte`, 출력 `qa-output/psd-matte`, 독립 검사 `verify_psd_matte_outputs.py`를 보존했다.

## 50 — 네이티브 회색조 PSD/PSB 저장

## 51 — RAW 센서 읽기/현상·원본/설정 보존

## 78 SVG 이미지의 원본/표시용 파일 추출

선택 image/feImage의 원래 data URI/원본 자산과 표시 파일을 추출한다. 원본은 정확한 보관 바이트이며 표시 파일은 방향/첫 화면/정밀도 표시를 정규화한 이미지다. 레이어의 변형·불투명도·마스크를 굽지 않는다. SVG는 원본 파일의 소스 바이트와 로컬 이미지가 내장된 표시 소스를 구분한다. 직접 PNG/WebP 참조도 파일명/원래 참조를 보관하며, 내장 이미지의 긴 URI를 원본 참조 속성에 다시 복사하지 않는다. 원래 이름이 없으면 MIME/실제 형식과 요소 번호를 사용하고 경로/금지 문자/Windows 예약 이름을 기본 파일명에 사용하지 않는다.

원본/표시용 저장 버튼은 기존 단일 백그라운드 작업과 연결한다. 성공/오류·파일 대화상자 취소·문서/선택 변경·취소 신호·분할 쓰기 중 취소를 처리하고 원자적 저장 실패가 이전 출력을 유지한다. 문서 내용/이력은 바뀌지 않는다. 저장이 이미 완료된 파일은 뒤늦은 취소가 되돌리지 않는다. Windows 저장 창은 조작하지 않고 지정된 자체 출력 경로로 검사했다.

새3검사에서 PNG16/TIFF16/음수 HDR EXR·PNG/정적 WebP/JPEG 방향/APNG/애니메이션 WebP/선형32·CFA DNG/JP2/JXL12입력을 추출하고 바이트 동등성·정밀도/RAW 원본 센서·프로젝트/SVGZ·이전 내장 JPEG의 방향과 기본 확장자·중첩 SVG의 다른 폴더 복원·잘못된 원본/참조/파일명·중간 취소 후 이전 파일을 확인했다. `verify_svg_extraction_outputs.py`가 별도 원본 SHA/메타데이터·APNG3프레임/WebP3프레임/PNG 픽셀/XML/gzip와 이전 출력 보존을 독립 검사했다. 이전16자산/20방향·첫 화면/9교체 속성 독립 자료와 1·2배 DPI 작은 창 입력도 다시 통과했다. 전체367통과/0실패/1제외·fmt/clippy·개발/release 빌드 통과. 자료 `qa-output/svg-assets/extract`, `extract-nested`. 다음은 RAW 색온도·틴트다. 원격 자산/외부 글꼴·CSS·동적 요소·고정밀 SVG/ICC·애니메이션 재생과 전체 다른 목표/실제 창 검증은 남는다. 자동 실행/화면 조작 금지는 유지한다.

## 94. JP2 표시 해상도 정보·정확한 ppi 분수

JP2 전용 포함/해제와1–65535ppi 입력을 추가했다. 기본은 해제/72ppi이며 J2K는 설정을 표시하거나 기록하지 않는다. native 안전 API `set_jp2_display_resolution_ppi`는 JP2 encoder만 받으며0/J2K/decoder를 거부하고 None은 이전 출력을 유지한다. 내부 선택 필드와 기존 JP2 header writer에26바이트 res /resd를 연결했다. 단위는 pixels/metre이며 ppi/254×10^4를 사용해 모든 u16 ppi를 정확하게 표현한다. 촬영/capture 해상도 값을 만들어 넣지 않는다. JP2와 J2K의 전체 바이트가 같다는 초기 QA 가정은 올바르지 않았다. 기존 `opj_j2k_update_rates`는 stream 위치를 파일 헤더 예산에 반영하므로 JP2/J2K와26바이트 메타데이터의 포함 여부는 중간 품질 패킷을 달리 배분할 수 있다. 이것을 픽셀 크기 변경/원본 수정과 구분하며 숫자만 바꾼 코드스트림과 별도 디코딩을 검사한다. 허용 픽셀 오차를 늘리지 않았다.

## 95. JPEG2000 입력 채널/부호·정밀도와 변환 오류 안정성

기존 DynamicImage::try_from의 채널 zip→버퍼 expect 경로는 실제로 채널 크기가 다른 정상 샘플링 파일에서도 panic을 일으킬 수 있었다. 새 `jpeg2000_input`은 크기/1–4채널/1–16비트/색상 공간/2채널 알파 정의를 먼저 확인하고 설명 있는 오류로 변환한다. 아직 처리하지 않은 샘플링/다중 채널/다른 색 공간을 억지 RGB로 읽지 않고 전체 호환 목표는 유지한다.

## 96. 동일 해상도 sYCC JPEG2000 색 변환·RGB 편집

sYCC3색 채널이 같은 크기/무부호/같은 정밀도인 JP2를 RGB로 읽고 변환 안내를 표시한다. 밝기/중심 크로마의 전체 범위 변환을 원래 깊이에서 수행해 정수 RGB로 제한한 뒤 출력 정밀도에 맞춘다. 네 번째 투명도도 유지하며32비트 작업 원본을 임의로 생성하거나 입력 파일을 수정하지 않는다. [OpenJPEG 표시 변환](https://github.com/uclouvain/openjpeg/blob/master/src/bin/common/color.c)의 sYCC 행렬/정수 표시 관례를 참고했으며 외부 구현 코드를 복사하지 않았다. sYCC 전체 색 관리/ICC와 구분한다.

자체8/12/16비트·RGB/알파6JP2/210픽셀·극값/정수 범위·프로젝트/PNG16bit/원본. `verify_jpeg2000_sycc_outputs.py`는 C OpenJPEG의 원시 성분을 보존한 채 독립 NumPy 벡터 행렬·클리핑/배율로 확인하고 출력 PNG 정수는 정확히 일치한다. float 표현6e-8 이내,8비트 Pillow 표시도1단위 이내다. ## 98. 샘플링 정렬의 0이 아닌 sYCC 시작 좌표

SIZ의 Xsiz/Ysiz를 절대 끝 좌표로 읽고 시작을 뺀 전체 밝기 크기와 각 성분의 ceil(끝/간격)-ceil(시작/간격)를 확인한다. 4:2:2는X를2에 정렬하고Y는 임의 시작,4:2:0은X/Y를2에 정렬한다. 디코딩된 성분 상대 좌표를 전체 이미지의 상대 픽셀에 연결하며 원본 위치가0이라는 가정을 제거했다. 부정 간격/뒤집힌 경계/불일치는 오류로 유지한다.

## 99. 비정렬 sYCC 시작·빈 색 성분 오류 처리

디코딩된 이미지 시작의 간격 나머지를 상대 픽셀에서 빼고, 남는 좌표를 크로마 간격으로 나눠 샘플 격자를 연결한다. 첫 행/열에 대응하는 색 샘플이 없으면 원시Cb/Cr=0으로 변환하고 가져오기 안내를 표시한다. 중심 크로마를0이라고 가정한 중립색 대체가 아니다. ## 100. JPEG2000 CMYK·알파의 RGB 편집 연결

COLR의CMYK 입력은4색·선택적5번째 정의된 알파로 읽는다. 각 색과 검정의 원래1–16비트 범위를 독립적으로 정규화한 보색 곱으로 RGB를 계산한다. 중간8비트 양자화 없이64비트 정수 분자/분모를 사용하여 최종8/16비트 정밀도를 유지하며 알파는 별도 부호/정밀도 정규화를 적용한다. CMYK 색 채널의 부호·잘못된 수/샘플링·5번째 알파 미정의는 오류로 반환한다. 프로파일 없는 변환임을 가져오기에서 알리며 ICC 인쇄색/CMYK 네이티브 편집·출력 완료로 표시하지 않는다. [OpenJPEG 색 변환 도구](https://github.com/uclouvain/openjpeg/blob/master/src/bin/common/color.c)의 보색 곱 관계를 참고했으며 코드는 직접 작성했다.

전체430통과/0실패/1제외·fmt/clippy·개발/release 빌드 통과. 이전84채널/정밀도·216비정렬 경계 독립 검사를 유지했다. `qa-output/jpeg2000-input/cmyk`, `cmyk-errors`. 실제 화면 조작은 하지 않았다. ICC/인쇄색·CMYK 네이티브 편집/출력·eYCC/빈 성분·전체 ISO/외부 앱/대형은 남는다. 다음101은 RAW 통합 보정 섹션이다.


## 101. RAW 통합 보정 섹션·최신 미리보기/적용

현상 창에 기존 레이어 보정과 같은 톤/4곡선·색상 믹서/그레이딩·톤 대비·노이즈/세부 선명화·Lensfun 프로파일/수동 교정 위젯을 연결했다. 열 때 현재 레이어 보정을 복원하고 범위/그 밖의 기존 설정을 유지한다. 초기화도 보정 범위는 유지한다. 원래 RAW 설정·보정·샘플 선택 모드 전체를 미리보기 키로 사용하고 오래된 작업 결과를 거부한다. 현상 후 보정은 작업자 스레드에서 계산해 전체/100% 비교에 표시하며 보정 자체는 레이어 메타데이터로 유지한다. 경계 확산은 레이어 내부를 미리보고 실제 문서 출력에서는 기존 외곽 합성 정책을 유지한다.

보정만 바뀌면 현재 픽셀의 공유 자산을 유지해 RAW 위에 직접 그린 내용을 교체하지 않는다. RAW 설정을 바꿨거나 화이트 밸런스 샘플을 고를 때는 실제 센서 원본을 다시 현상한다. 후자의 경로를 기존 실패/재시도 검사에서 확인해, 편집한 픽셀을 센서 샘플로 사용하는 오류를 막았다. 스포이드는 렌즈/색 보정 전 화면에 연결한다. 적용 시 RAW 결과/설정과 보정을 한 레이어 변경·한 번 이력으로 저장하며 취소는 문서를 변경하지 않는다.

## 102. RAW 좌우 보정 패널·작은 창 전환

## 120. PNG/JPEG/WebP EXIF 출력·기존 방향/치수 갱신

## 121. PNG/JPEG/WebP/TIFF XMP 출력·기존 방향/치수 갱신

촬영 XMP 포함 선택(기본 포함)을4형식에 연결하고 실제 headless 토글/취소·미리보기 옵션 키·문서 이력/원본 불변을 확인했다. UTF-8 XML 원문의 기존 tiff:Orientation은1, tiff:ImageWidth/ImageLength와 exif:PixelX/YDimension은 작업 크기로 바꾼다. 네임스페이스 URI로 속성·요소·CDATA·qualified rdf:value·빈 요소·긴 속성 공백을 찾아 원래 접두어/알 수 없는 속성·한글·주석·패킷 구조를 유지한다. 원본 자산은 변경하지 않고 출력에서 xmp:Thumbnails를 제거한다. URI 방향 값/중복 rdf:value/비정상 RDF 구조의 오류를 실제 실패 검사로 재현하고 거부하도록 수정했다. 미지원 인코딩·손상 XML·확장 XMP 참조·JPEG APP1 초과는 기존 파일을 보존하고 포함 옵션을 끄면 저장할 수 있다.

PNG는 IHDR 뒤 iTXt/CRC, JPEG는 APP1 식별자, WebP는 VP8X XMP 플래그/XMP 청크·기존 ALPH/VP8/VP8L, TIFF는 태그700(classic/BigTIFF)에 기록한다. [Adobe XMP 명세](https://developer.adobe.com/xmp/docs/xmp-specifications/), [TIFF 속성](https://developer.adobe.com/xmp/docs/xmp-namespaces/tiff/), [EXIF 속성](https://developer.adobe.com/xmp/docs/xmp-namespaces/exif/), [WebP 컨테이너](https://developers.google.com/speed/webp/docs/riff_container)를 확인했다. 의존성/외부 코드를 추가하지 않았다.
